Hardware-Attached Simulation
¶
CANivore supports hardware-attached simulation when used in an
FRC robot program
. This allows a CANivore to be used with real devices on supported host operating systems. The below video showcases controlling a
real
Falcon 500
in a robot program using hardware-attached simulation.
To utilize hardware-attached simulation, ensure the CANivore is connected directly via USB to the machine running the simulation. All devices on the CANivore CAN Bus should be independently powered, as the CANivore does not provide power. In the robot program, the CANivore name or
*
must be specified in the device constructor.
Important
Any motors/actuators that have been connected to a roboRIO CAN Bus at any time must be factory defaulted due to them being
FRC Locked
. Factory defaulting can be done in
Tuner X
and should be done when the CANivore is
not
connected to a roboRIO.

Users may notice the robot program is using simulated devices by default. This is the default behavior if the host platform supports simulation (see
requirements
for a full list of supported platforms).
In order for the robot program to communicate with physical devices (on platforms that support both simulation and hardware), the
CTR_TARGET
environment variable must be set. Examples of this are shown below.

# Set the environment variable only for the python call
